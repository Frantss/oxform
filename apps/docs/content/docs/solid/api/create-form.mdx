# createForm

`createForm(options)` returns a stable `CreateFormReturn<Values, Checks>` with core form methods and reactive status getters. Values infer from `schema`; configured checks infer issue levels, with `error` always included. Options may be an object with getters or an accessor.

```tsx twoslash
// @jsx: preserve
// @jsxImportSource: solid-js
import { createField, createForm } from '@oxform/solid';
import { z } from 'zod';

function EmailForm() {
  const form = createForm({ schema: z.object({ email: z.email() }), defaultValues: { email: '' } });
  const email = createField({ form, name: 'email' });
  const submit = form.submit(values => {
    console.info(values.email);
  });

  return (
    <form
      onSubmit={event => {
        event.preventDefault();
        void submit();
      }}
    >
      <input aria-label='Email' {...email.props} />
      <button type='submit' disabled={form.status.submitting}>
        Submit
      </button>
    </form>
  );
}
```

## Options

| Option               | Contract                                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------------------- |
| `schema`             | Required Standard Schema validator. Infers values and supplies default submit validation.                     |
| `defaultValues`      | Required initial values and reset baseline. Creation does not validate them.                                  |
| `id`                 | Optional identifier, generated if omitted. Fixed after creation.                                              |
| `defaultStatus`      | Initial overrides for `dirty`, `submits`, `submitting`, `validating`, and `successful`. Reset reapplies them. |
| `defaultFieldStatus` | Initial `dirty`, `touched`, and `blurred` overrides by path; `'*'` supplies common defaults.                  |
| `checks`             | Validators keyed by issue level and event, with optional blocking flags.                                      |

Reactive updates change configuration for later operations. Updating defaults does not overwrite current values; call `reset()` to apply the new baseline.

## Properties

| Property        | Contract                                                                                                             |
| --------------- | -------------------------------------------------------------------------------------------------------------------- |
| `id`, `options` | Identifier and current configuration.                                                                                |
| `values`        | Imperative current-values snapshot; use [createSubscribe](/docs/solid/api/subscribe) to observe it.                  |
| `state`         | Stable reactive getters for `values`, `fields`, root-only `issues`, and `status`; `state.status === form.status`.    |
| `status`        | Stable container with reactive [status getters](/docs/solid/api/status).                                             |
| `store`         | Observable store containing values, fields, root-only issues, and status.                                            |
| `field`         | Path-based `get`, `status`, `change`, `focus`, `blur`, `register`, `unregister`, `issues`, `setIssues`, and `reset`. |
| `array`         | Path-based `insert`, `append`, `prepend`, `swap`, `move`, `update`, `remove`, and `replace`.                         |

Path-based operations use the same contracts as [bound fields](/docs/solid/api/create-field) and [bound arrays](/docs/solid/api/create-array-field), with the path as their first argument. `form.field.register(name)` returns an element callback.

`form.issues()` reads root issues as a snapshot; `{ nested: true }` includes all field issues. `form.setIssues(issues, options?)` writes only root issues, using the same replace, append, and keep modes as field writes. Use `form.state.issues` to render request-wide failures reactively; a whole-form error validation clears previous root errors, while targeted field validation leaves them unchanged.

## `validate(fields?, options?)`

Returns `Promise<[boolean, FormIssuesByLevel<Level>]>`. Omit targets for whole-form validation, or supply a path or list of paths for their subtrees. Validators receive the full values object; targets limit returned issues and updated paths.

`options.type` selects `change`, `blur`, `focus`, or `submit`. Omitting it runs the root schema and all configured events. The boolean describes blocking issues emitted by this run; `form.status.valid` describes all current issues. See [Validation](/docs/solid/guide/validation).

```ts
const [valid, issues] = await form.validate('email', { type: 'blur' });
await form.validate();
```

## `submit(onSuccess, onError?)`

Returns a zero-argument `() => Promise<void>` handler. It runs whole-form submit validation, then awaits `onSuccess(values, form)` if both the run and current aggregate validity pass, or `onError(issues, form)` otherwise. Validators and the success callback receive the same captured raw values, not schema-transformed output.

Invocation synchronously marks the form dirty and submitting. Concurrent calls on one form share the active attempt and the first call's callbacks. A value change, superseding validation, or reset before the callback aborts without calling either callback or retrying automatically.

Every settled attempt clears `submitting` and increments `submits`, including stale and rejected attempts; a reset's replacement status is preserved. Validator or callback rejection rejects the handler and leaves `successful` false. A resolved valid callback sets `successful` true; that is not proof of server acceptance. Prevent browser submission in your DOM handler.

## `reset(options?)`

Restores defaults, clears issues and refs, recreates fields, and resets submit status. It does not validate. `values` supplies a full values object for this reset without changing the default baseline; `status` overrides reset status.

| Keep option                          | Behavior                                                                                                                      |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| `issues: true` or an array of levels | Preserve all issues or selected levels at retained paths.                                                                     |
| `refs: true`                         | Preserve registered elements at retained paths.                                                                               |
| `fields: true`                       | Preserve complete field state, including IDs, status, refs, and issues. Takes precedence over other field preservation flags. |

```ts
form.reset();
form.reset({ keep: { refs: true, issues: ['error'] } });
```

Solid manages the internal mount and configuration-update calls. See [Lifecycle](/docs/solid/guide/reactivity) for disposal and server rendering.
