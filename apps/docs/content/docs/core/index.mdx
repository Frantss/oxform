# Oxform Core

`oxform-core` exposes forms independently of a UI framework. Its values, status, validation, reset, and array contracts also apply to [React](/docs/react) and [Solid](/docs/solid) bindings.

## Form

### `createForm(options)` and `new FormApi(options)`

Create a form from a Standard Schema validator and matching initial values. `createForm` infers issue levels from checks keys; direct class construction permits explicit value and level generics.

```ts twoslash
import { createForm, formOptions } from 'oxform-core';
import { z } from 'zod';

const options = formOptions({
  schema: z.object({ email: z.string(), tags: z.array(z.string()) }),
  defaultValues: { email: '', tags: ['alpha'] },
});
const form = createForm(options);

form.field.change('email', 'ada@example.com');
form.array.append('tags', 'beta');
```

Direct constructors expose the same core APIs. Supply class generics when you need precise value types; the factories infer them from the schema and field path.

```ts twoslash
import { ArrayFieldApi, FieldApi, FormApi } from 'oxform-core';
import { z } from 'zod';

const schema = z.object({ email: z.string(), tags: z.array(z.string()) });
const form = new FormApi<z.input<typeof schema>>({
  schema,
  defaultValues: { email: '', tags: [] },
});
const email = new FieldApi<string>({ form, name: 'email' });
const tags = new ArrayFieldApi<string[]>({ form, name: 'tags' });

email.change('ada@example.com');
tags.append('customer');
```

### `formOptions(options)`

Returns the supplied configuration, preserving inferred value and issue-level types. It does not create form state or run validation. Both `oxform-react` and `oxform-solid` re-export it.

### Properties and Methods

| Member                        | Contract                                                                  |
| ----------------------------- | ------------------------------------------------------------------------- |
| `id`                          | Supplied or generated identifier.                                         |
| `options`                     | Current configuration.                                                    |
| `values`                      | Current values snapshot.                                                  |
| `status`                      | Current aggregate form status.                                            |
| `store`                       | Read-only observable store with values, field state, and form status.     |
| `field`                       | Path-based field operations listed below.                                 |
| `array`                       | Path-based array operations listed below.                                 |
| `validate(fields?, options?)` | Returns a promise of run validity and emitted issue buckets.              |
| `submit(onSuccess, onError?)` | Returns an async zero-argument submit handler.                            |
| `reset(options?)`             | Restores values, field state, and form status with optional preservation. |
| `'~mount'()`                  | Returns cleanup for adapter lifecycle integration.                        |
| `'~update'(options)`          | Updates configuration without resetting current values.                   |

The [form reference](/docs/react/api/use-form) describes each option, reset flag, and submit transition. The [validation guide](/docs/react/guide/validation) covers events, field scopes, replacement, and asynchronous results. Core reads are snapshots; subscribe through `store.subscribe` or `createEffect` to observe changes.

## Field

### `createField({ form, name })` and `new FieldApi(options)`

Return an API bound to one path. Prefer the factory for path-to-value and issue-level inference.

```ts twoslash
import { createField, createForm } from 'oxform-core';
import { z } from 'zod';

const form = createForm({ schema: z.object({ email: z.string() }), defaultValues: { email: '' } });
const email = createField({ form, name: 'email' });

email.change(current => current.trim());
email.focus({ should: { validate: false } });
email.blur();
email.get();
email.issues();
email.setIssues({ error: [{ level: 'error', issue: { message: 'Already registered' } }] });
email.reset();
```

The bound API exposes `options`, `id`, `value`, `state`, and `store` properties. Its methods are `get`, `change`, `focus`, `blur`, `register`, `unregister`, `issues`, `setIssues`, and `reset`. It exposes `'~mount'` and `'~update'` for adapters. It does not expose framework input props.

### `form.field`

| Method                                   | Usage                                            |
| ---------------------------------------- | ------------------------------------------------ |
| `get(name)`                              | Read the schema-derived value at a path.         |
| `status(name)`                           | Read path-specific field status.                 |
| `change(name, valueOrUpdater, options?)` | Write a direct value or updater result.          |
| `focus(name, options?)`                  | Focus the registered element and mark touched.   |
| `blur(name, options?)`                   | Blur the element and mark blurred.               |
| `register(name)(element)`                | Register an element; null is a no-op.            |
| `unregister(name)`                       | Clear its reference.                             |
| `issues(name, options?)`                 | Read issues, optionally including descendants.   |
| `setIssues(name, issues, options?)`      | Replace, append, or keep issue buckets.          |
| `reset(name, options?)`                  | Restore the field value and default field state. |

Bound methods have the same behavior with the name argument omitted. For status use `field.state.status`; for registration call `field.register(element)`. See the [field reference](/docs/react/api/use-field) for change flags, issue modes, and reset limitations.

## Array Field

### `createArrayField({ form, name })` and `new ArrayFieldApi(options)`

Return an API bound to an array-valued path. The factory infers its array value, item value, and issue levels.

```ts twoslash
import { createArrayField, createForm } from 'oxform-core';
import { z } from 'zod';

const form = createForm({ schema: z.object({ tags: z.array(z.string()) }), defaultValues: { tags: ['alpha'] } });
const tags = createArrayField({ form, name: 'tags' });

tags.append('beta');
tags.prepend('first');
tags.insert(1, 'middle');
tags.swap(0, 1);
tags.move(0, 2);
tags.update(0, current => current.toUpperCase());
tags.remove(0);
tags.replace(['alpha']);
tags.get();
tags.ids;
```

Properties are `options`, `store`, `state`, and `ids`. It also exposes `'~mount'` and `'~update'`. Read array values with `get()` or `state.value`; there is no `value` shortcut.

`form.array` exposes the same mutations with the path as the first argument, for example `form.array.insert('tags', 0, 'alpha')`. Read values through `form.field.get('tags')`. See the [array reference](/docs/react/api/use-array-field) for item identity, index normalization, updater behavior, and validation exceptions.

## Effect

### `createEffect(api, selector, callback)`

Observes selected form, field, or array state. It skips the initial value and invokes the callback only when the selection changes by deep equality. Returns a subscription with `unsubscribe()`. Async callbacks may overlap.

```ts twoslash
import { createEffect, createForm } from 'oxform-core';
import { z } from 'zod';

const form = createForm({ schema: z.object({ email: z.string() }), defaultValues: { email: '' } });
const subscription = createEffect(
  form,
  state => state.values.email,
  email => {
    console.info(email);
  },
);

form.field.change('email', 'ada@example.com');
subscription.unsubscribe();
```
