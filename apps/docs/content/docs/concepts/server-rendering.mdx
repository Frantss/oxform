## In short

A form is shared, and an instance is made for each render or each request. The `api` of each extension is inert at
creation, so an instance does no work on a server. The adapter gives the form id, so the ids match after
hydration.

## Model

- A form lives at module scope. It holds no state, so all requests can share it.
- `Root` of an adapter makes one instance for each render. A request handler makes one with `form.create(options)`.
- `form.create` runs the `api` of each extension. No built-in extension starts a timer, a request or a validation
  run there.
- The pure members of a slot (`text`, `present`, `state` and `attrs`) render on a server. `on` and `bind` run in a
  browser only.
- `Root` passes an id from the framework (`useId` in React, `createUniqueId` in Solid) to `create`. Field ids come
  from the form id. An `id` option that you give wins.
- `form.create()` with no `id` and no adapter takes an id from a counter, such as `form-1`.
- A handler can create an instance, await `validation.run()`, and render that instance with `<Root form={form}>`.
  `Root` then uses the instance and its options as they are.

## Rules

- Define each form at module scope. Do not make an instance at module scope.
- Make one instance for each render or each request.
- `api` must not touch the DOM, start a timer or send a request at creation.
- Pass an `id` to `create` when you render an instance without an adapter on both the server and the browser.
- No adapter calls `destroy()`, on a server or in a browser. A server instance holds no work.
- Do not call `createEffect` inside `api`.

## Example

The sign-in page is rendered on the server, and the ids and the values must match after hydration (E26). The form
lives at module scope and holds no state. It sets no id, so each instance takes the id that the adapter gives.

```ts twoslash
import { defineForm } from '@oxform/core';
import { standard } from '@oxform/core/presets';
import { z } from 'zod';

const schema = z.object({ email: z.email(), password: z.string().min(8) });

// Module scope: one form for every request. It holds no state.
export const signInPage = defineForm({ schema, defaultValues: { email: '', password: '' } })
  .extend(standard)
  .configure({ error: { submit: schema }, onSubmit: async credentials => console.log(credentials.email) });

// Each render or request: one instance. `Root` makes it, with the id of the framework.
export const render = (id: string) => {
  const form = signInPage.create({ id });
  return form.field('email').state.id;
};
```

`render('r1')` gives the field id `r1-email`, on the server and in the browser. The kit holds the same form as
`sign-in-page.ts`, on the lean sign-in chain.

## Common mistakes

| Wrong code                                                             | Effect                                                                         | Fix                                          |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------- |
| `export const form = signInPage.create()` at module scope              | Every request shares one instance, and the state of one user leaks to the next | Make one instance per render or per request  |
| `create()` with no `id`, rendered by hand on a server and in a browser | The counter ids `form-1` can differ, and hydration fails                       | Pass the same `id` to `create` on both sides |
